Do not enlarge it. --- ## Task 1 — reject trailing content after the closed array **CAM-298**, found by ORDER CD's own test and left unfixed there by scope. Owner decision: **reject.** A payload of the form `[]}{` currently returns its shapes and throws nothing. The streaming branch calls `beginArray()`, reads to the closing bracket, and never calls `endArray()`; `close()` does not validate. Anything after the array's close is silently ignored. **Why reject rather than accept.** This is not an attack surface — the Ed25519 signature covers the whole payload, so an attacker cannot append anything and have it verify. The only route to trailing content in a verified file is **ULGS signing one**: a prep-tool defect, a truncated write before signing, a concatenation mistake in a script. The argument for accepting it is that the signature bounds the risk, which is the argument that we would not make that mistake. ORDER CD's finding was that **a partial result is indistinguishable from a complete one at every layer above it.** Trailing content is the same shape from the other end: a payload that is half-written and signed draws its first half as though whole. The parser should say so. **The change:** after the array closes, call `endArray()` and confirm the stream holds nothing further. On failure the existing catch returns `emptyList()` — CD's behaviour, unchanged — and the boundary surfaces as unavailable rather than drawing partial geometry. **The test must fail before the fix.** Report the failing output verbatim. Two cases and a control: - `[]}{` → currently 1 shape, required 0 - `[] ` → same - **Control:** `[]` with nothing after it → must still return **1**, or the fix has merely made the parser return nothing. `BoundaryStreamParseTest` is the home — androidTest, for the reason ORDER BZ §9 records. --- ## Task 2 — check the change against files that already exist **A stricter parser meets files signed under the looser one.** Before reporting Task 1 complete, verify that every `.telcam` container already produced still parses. - The golden fixture at `app/src/androidTest/assets/fixtures/golden-20260830.telcam` — it exists precisely to catch format drift and **must still verify and still parse**. - The negative fixtures must still be rejected, and for the same reasons as before, not newly for this one. - Any container in the repo or produced by `tools/ulgs_prep.py` and `tools/bz_fixtures.py`. **If anything that used to pass now fails, stop and report it.** That would mean ULGS tooling has been emitting trailing content, which is a finding about the prep pipeline and not a reason to soften the parser.
